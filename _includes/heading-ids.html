{%- comment -%} Gives the headings of a translated page the anchors of the English page, and outputs the result. Usage: {% include heading-ids.html html=rendered_body %} kramdown derives a heading's id from its text, so every translation had anchors of its own: #setup in English, #configuration in French — where #configuration is also what the next heading gets in English. A link carried from one language to another, or a fragment kept by the language picker, landed on the wrong section or nowhere. The id cannot be written in the page: `## Setup {#setup}` would hand `{#setup}` to translators along with the heading, the same reason the front matter carries no identifier. But a Weblate translation is the English page with its strings replaced, so its headings come in the same order, at the same levels — the n-th heading of a translation is the n-th heading of the English page, and takes its id. That holds only while both files are in step. When the sequences of levels differ — a translation not yet rebased on a changed page, or one written by hand — the page keeps its own ids rather than get wrong ones. The English page is read through `markdownify`, because whether `content` still holds its Markdown or already holds its HTML depends on which page Jekyll renders first. kramdown passes rendered HTML blocks through untouched, so both forms give the same ids. `path_lang` and `known_langs` come from i18n.html. {%- endcomment -%} {%- assign hid_source = nil -%} {%- assign hid_default = site.default_lang | default: 'en' -%} {%- assign hid_siblings = site.pages | where: 'name', page.name -%} {%- for sibling in hid_siblings -%} {%- include page-lang.html url=sibling.url -%} {%- if derived_lang == hid_default and sibling.url != page.url -%} {%- assign hid_source = sibling -%} {%- break -%} {%- endif -%} {%- endfor -%} {%- assign hid_done = false -%} {%- if hid_source -%} {%- comment -%} A heading opens as `
